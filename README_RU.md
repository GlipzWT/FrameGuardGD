# FrameGuard — исходники экспериментальной альфы

**Статус: v0.1.0-alpha.1, прототип, а НЕ законченный проверенный мод.**

Цель: подбирать момент нажатия/отпускания Wave в пределах 0–10 физических
шагов. В проекте есть меню, настройки, отдельные бинды, алгоритм выбора
ближайшего предполагаемо безопасного момента, а также отключаемая
экспериментальная локальная коррекция прошлого состояния игрока.

**Нельзя обещать, что этот код не даст игроку умереть.** Предиктор приближённый,
а работа Geode-части ещё требует полной сборки под Windows и проверки в игре.
Успех тестов алгоритма сам по себе не означает, что игровые хуки работают.

## Целевая конфигурация

| Компонент | Версия / ограничение |
|---|---|
| ОС | Windows x64 |
| Geometry Dash | 2.2081 |
| Geode SDK | 5.11.2 |
| Режим игры | Только Practice Mode |
| Игрок | Один Wave, обычное движение вправо |
| Мир | Простые статичные объекты без триггеров, склонов и динамики |
| Другие физические моды | На первых тестах выключить CBF, TPS bypass, speedhack и прочие изменения физики |

Версии выбраны явно, а не определены из установленной у вас игры. Для другой
версии GD/Geode или Android понадобится адаптация и отдельная сборка.

## Что уже написано

- Настраиваемое окно **0–10** физических шагов; 0 выключает коррекцию.
- Отдельная коррекция нажатий и отпусканий.
- Выбор ближайшей подходящей задержки. Если немедленный ввод по модели
  безопасен, он остаётся неизменным.
- **Локальный rollback по желанию**, по умолчанию выключен.
- Тёмное меню с акцентным цветом, слайдером, кнопками `−`/`+`, переключателями
  и отдельным описанием ограничений.
- Бинд открытия меню **F7**, бинд включения помощи **F8**.
- Оба бинда меняются в настройках Geode.
- Кнопка `FG` в главном меню и статусный HUD.
- Сброс истории при рестарте, загрузке practice-checkpoint, смене состояния
  игрока, паузе, выходе и изменении важных настроек.
- Запрет работы вне Practice Mode, в dual/platformer и на неподдерживаемых
  уровнях. При отказе обычный ввод проходит без коррекции.
- Тесты независимого алгоритма и workflow Windows-сборки GitHub Actions.

## Чего здесь НЕТ

1. **Полного rollback движка.** Не восстанавливаются часы уровня, музыка,
   камера, триггеры и произвольные динамические объекты.
2. Точного штатного collision oracle GD. Проверяются консервативные AABB
   прямоугольники и непрерывные отрезки траектории. Поворотные шипы, saw-hitbox,
   специальные правила Wave, D-блоки, реальные границы камеры/потолка и т. д.
   могут не совпасть с моделью. Даже на статике возможно неверное решение.
3. Поддержки всех режимов, dual, platformer, slopes, reverse, sideways,
   teleport, смены физики во время окна и уровней с триггерами.
4. Подтверждённой совместимости с модами ввода, replay, TPS или speedhack.
5. Гарантии прохождения длинного участка: горизонт прогноза конечный.
6. Проверенного готового `.geode` в этом архиве. Нужна сборка, затем тестирование.

Если нужен именно надёжный универсальный вариант из первоначального описания,
эту версию нельзя считать выполненной конечной реализацией. Это первый
исходный прототип для дальнейшей отладки на конкретной версии игры.

## Как работает коррекция

### Rollback выключен

1. Хук `handleButton` получает реальный ввод первого игрока.
2. Проверяются Practice, Wave и допустимость уровня.
3. По последнему наблюдаемому смещению оценивается горизонтальная скорость.
4. Для текущего действия проверяются задержки `0, 1, …, N`.
5. Выбирается первая траектория, не пересекающая препятствия в модели.
6. Отложенное действие применяется перед выбранным `PlayerObject::update`.
7. Если безопасного предложения нет, ввод передаётся без коррекции.

Ввод не переносится назад. Нет бессмертия, удаления шипов или увеличения хитбокса
уровня. При слишком быстром противоположном вводе отложенный фронт сначала
применяется, затем новый фронт проходит сразу: порядок сохраняется, но коррекция
такой быстрой пары пропускается. Оба события могут попасть в один физический шаг.

### Локальный rollback включён

- Хранятся последние `PlayerCheckpoint` и состояния линейной Wave-модели.
- При новом вводе проверяются отрицательные смещения до `−N`, не переходя через
  предыдущее физическое событие ввода.
- Если найден более близкий вариант, восстанавливается checkpoint **игрока**.
  Затем положение игрока доводится до настоящего по линейной модели с новым
  моментом ввода. Это не повторное исполнение всего движка GD.
- При первом допустимом столкновении смерть временно подавляется, чтобы дать
  опоздавшему вводу шанс прийти. **Это кратковременное подавление collision-death**,
  то есть в течение grace-периода игрок может визуально проникнуть в препятствие.
- Срок grace не продлевается повторными столкновениями. Если корректный прошлый
  путь не найден или ввод не пришёл, вызывается обычная смерть.
- Для спасения нельзя выбрать состояние уже ПОСЛЕ первого смертельного
  столкновения: проигрываемая модель должна включать этот контакт и избежать его.
- При паузе, выключении помощи или изменении настроек неразрешённая grace-смерть
  фиксируется, а не превращается в постоянный noclip.

**Этот режим экспериментальный.** Ограничение на статичные уровни необходимо
именно потому, что локальный откат не восстанавливает мир. Обнаружение
неподдерживаемого уровня специально очень строгое: даже удалённый триггер может
выключить помощь на всём уровне. Улучшать охват ослаблением этой проверки нельзя
без разработки полноценного сохранения состояния мира.

### Что считается кадром

Один `frame` в этой альфе — один наблюдаемый вызов физического обновления
`PlayerObject::update` первого игрока. Это **не** кадр монитора и не гарантированная
длительность в миллисекундах. Частота физических шагов зависит от игры и других
модов; после изменения длительности шага история сбрасывается. Не следует считать
«5 кадров» автоматически равными `5 / FPS монитора` секундам.

## Способ 1 — получить `.geode` через GitHub Actions

Можно обойтись без локальной установки C++-компилятора.

1. Распакуйте архив. Корень проекта — папка, в которой лежит `mod.json`.
2. Создайте свой репозиторий GitHub и загрузите **все** файлы проекта, включая
   скрытую папку `.github/workflows`. Удобно использовать GitHub Desktop или Git.
   Не загружайте проект только как один ZIP: workflow должен находиться в
   `.github/workflows/build.yml` самого репозитория.
3. Откройте вкладку **Actions → Build Windows Geode mod → Run workflow**.
   Если GitHub предлагает разрешить workflows в вашем репозитории, включите их.
4. Сначала запускаются тесты планировщика. Затем Windows runner устанавливает
   SDK нужной версии и собирает мод.
5. Дождитесь зелёного результата. В разделе **Artifacts** скачайте
   **FrameGuard-Windows-alpha** и распакуйте скачанный архив.
6. Найдите внутри файл **`r7324507.frameguard.geode`**. Если загрузились также
   отладочные файлы `.pdb`, для установки мода они не обязательны.

**Workflow включён в исходники, но не был запущен в вашем GitHub.** Его наличие
не означает, что пакет уже собран. Если Windows job красный, `.geode` не готов:
откройте первый C++/CMake error в `Build with pinned Geode SDK`. Не пытайтесь
просто переименовать архив с исходниками в `.geode`.

Workflow не требует паролей или токенов в исходниках. Он запускается только
в вашем репозитории. Перед запуском можно просмотреть весь YAML.

## Способ 2 — сборка на Windows

### 1. Установите инструменты

- Git.
- Visual Studio 2022 / Build Tools с workload **Desktop development with C++**:
  MSVC x64/x86, Windows SDK, CMake tools. Используйте актуальный toolset.
- Geode CLI. Например, в PowerShell:

```powershell
winget install --id GeodeSDK.GeodeCLI -e
```

Перезапустите терминал и проверьте:

```powershell
geode --version
git --version
cmake --version
```

Если CMake/MSVC не обнаруживаются, используйте **Developer PowerShell for
VS 2022**, а не обычный терминал без окружения компилятора.

### 2. Установите и зафиксируйте SDK

В примере SDK устанавливается в `C:\GeodeSDK`. Если эта папка уже занята,
не переустанавливайте существующий SDK вслепую — используйте отдельную папку.

```powershell
geode sdk install C:\GeodeSDK
cd C:\GeodeSDK
git fetch --tags
git checkout v5.11.2
git submodule update --init --recursive
$env:GEODE_SDK = "C:\GeodeSDK"
geode sdk install-binaries -p win -v v5.11.2
```

Переменная `$env:GEODE_SDK` выше действует в текущем терминале. При открытии
другого терминала задайте её заново, если CLI не сохранил системную переменную.

### 3. Соберите проект

Перейдите в распакованную папку, где лежит `mod.json`:

```powershell
cd C:\Projects\frameguard
$env:GEODE_SDK = "C:\GeodeSDK"
geode build
```

Официальный альтернативный путь:

```powershell
cmake -B build -A x64
cmake --build build --config RelWithDebInfo
```

При использовании Ninja, а не Visual Studio generator:

```powershell
geode build --ninja
```

Генераторы нельзя смешивать в одной папке `build`. При смене генератора используйте
новую папку сборки или удалите только старую папку `build`, не исходники.

После успешной сборки ищите `r7324507.frameguard.geode` внутри `build` (возможны
вложенные папки в зависимости от конфигурации). Только наличие успешного лога
и этого пакета означает, что сборка завершена.

## Установка и первый запуск

1. Полностью закройте GD. Сохраните резервную копию игровых сохранений.
2. Убедитесь, что установлены GD **2.2081** и совместимый Geode **5.11.2**.
3. Найдите каталог игры. Для Steam: **Manage → Browse local files**.
4. Скопируйте собранный `.geode` в `<каталог игры>\geode\mods\`.
5. Запустите GD. При ошибке загрузки удалите этот файл при закрытой игре.
6. Откройте меню `FG` или нажмите **F7**. Помощь изначально выключена.
7. Включите Practice на простом тестовом уровне с одним Wave и обычными
   прямоугольными препятствиями, без триггеров и склонов.
8. Включите помощь с окном 1–2; rollback пока оставьте **OFF**.
9. Посмотрите HUD. `Unsupported…` означает отказ от коррекции, а не поломку бинда.
10. Проведите проверки из `docs/TEST_PLAN_RU.md`. Только после этого пробуйте
    больший диапазон и локальный rollback на одноразовом тренировочном уровне.

Бинды: **Geode → FrameGuard → Settings → Open FrameGuard menu / Toggle assist**.
Внутри панели есть кнопка **Settings / binds**. Меню открывается с паузой;
закрытие панели не возобновляет игру автоматически.

Не используйте мод для рекордов или в соревнованиях и не выдавайте прохождение
с помощью за честное. Автоматического скрытия помощи, отправки рекордов или
обхода античита здесь нет; работа ограничена Practice.

## Независимые тесты без Geode

Linux / macOS с G++ или Clang:

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Werror -pedantic -Iinclude tests/planner_tests.cpp -o planner-tests
./planner-tests
```

Или через CMake:

```bash
cmake -S . -B build-core -DFRAMEGUARD_CORE_ONLY=ON
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

Тесты проверяют геометрию, выбор смещений, границы 0–10, отпускания,
невалидные данные, непрерывное столкновение и ограниченный grace. Дополнительно
проверяются 2000 псевдослучайных сцен. Они **не проверяют** SDK ABI, адреса хуков,
тайминг ввода в GD, интерфейс в игре или точность хитбоксов GD.
